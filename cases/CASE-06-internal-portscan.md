This search isolates outbound SYN packets sourced from the already-compromised Vista host (192.168.10.8) toward the internal web server (192.168.10.50), using the filter ip.src == 192.168.10.8 && ip.dst == 192.168.10.50 && tcp.flags.syn == 1 && tcp.flags.ack == 0. Wireshark returned 8,910 matching packets, spanning a wide, non-sequential range of destination ports — including 21, 22, 995, 999, 9943–9999, 15883, and 46405 — nearly all logged as TCP retransmissions because the destination did not respond. This establishes that the compromise identified in Case 5 was not the end state of the incident: the same host that received a Meterpreter shell over port 444 subsequently became the source of an internal scan against another asset on the network.

The port range itself is the key evidence. Legitimate application traffic clusters around a small number of expected ports; this traffic instead sweeps broadly and without an apparent service-driven pattern, which is characteristic of an automated scanning tool such as Nmap rather than a human-driven or application-driven connection attempt. The high retransmission rate (nearly every SYN times out rather than completing a handshake) further indicates the scanner was probing for open ports rather than communicating with a known service — 192.168.10.50 was not listening on the vast majority of ports attempted.

Correlating this with Case 5's timeline, the C2 channel to 205.174.165.73 was active in the same general window as this scanning activity, indicating the two behaviors were concurrent rather than sequential: the attacker maintained remote access to Vista while using it as a launch point for internal reconnaissance. This is consistent with the MITRE ATT&CK technique T1046 (Network Service Scanning) and represents the pivot stage described in the incident summary — the victim host converting into an internal attack platform.
